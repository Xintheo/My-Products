# BIO 项目设计逻辑总结

这是一个 Tauri 桌面应用,驱动基于 Obsidian vault 的工作流。以下按层面梳理我们确立的设计。

## 一、整体架构

四层,各司其职:

- **前端 App.tsx**(React/TS)—— 界面:工作流标签、步骤卡片、配置面板
- **后端 lib.rs**(Rust/Tauri)—— 命令桥接、文件扫描、系统调用
- **业务脚本**(Python,`scripts/`)—— runner.py 调度,bioinfo_tools/workspace_tools/base_tools 等干活
- **初始化脚本**(scaffold/generator/generate)—— 一键生成新项目

数据流:前端点步骤 → `invoke("run_step")` → lib.rs 起 Python 子进程跑 runner → runner 派发到业务脚本 → stdout 最后一行 JSON 回传。

## 二、配置键机制(核心设计)

这是整个项目最关键、也是我们反复纠正才立对的机制。

**配置键写在笔记自己的 frontmatter 里,不靠文件名。** 每个需要被程序引用的笔记,头部声明:

```yaml
---
配置键:
  - script_review_instruction
---
```

`lib.rs` 的 `sync_config_keys` **递归扫描整个 vault 根**,读每个 .md 的 frontmatter,把声明的配置键映射到该文件的**实际路径**,写进 config。要点:

- **文件名完全无关** —— 文件叫什么、在第几层目录,都无所谓,是文件自报配置键
- **扫整库,不指定子目录** —— 目录序号/结构怎么变都不影响
- **跳过隐藏目录**(`.obsidian` 等),避免插件里的 md 污染
- 触发时机:选库后自动扫、点「重建配置」时扫

这条原则我们踩了很多坑才立住:绝不硬编码文件名、绝不写死子目录路径去找文件。

## 三、前端配置面板

仿成熟工作流,**按文件夹分组**展示:

```
配置进度：5/5   ●●●●●
自动化目录（点击打开）
📁 AI指令
   📄 生信脚本评审指令  [script_review_instruction] ✓
   📄 分析脚本指令      [script_analyze_instruction] ✓
📁 中转站
   📄 原始脚本(1中转站)  [script_transit_store] ✓
   ...
```

设计细节:

- **配置键做成右侧灰胶囊**,和中文名同行,省纵向空间,点击可复制
- **文件夹/文件可点开**(`⇱`)—— 调 `open_in_system` 在系统里打开
- **进度点阵** —— 绿=就绪、黄=配了路径但文件不就绪、红=没配

**就绪判定分两类**(关键区分):

- **指令类** —— 要文件真实存在且非空(`check_file_status` 返回 ready)
- **中转站类** —— 一过性临时存储,**空着是常态**,只要配了路径就算就绪,绝不看内容

用 `folder === "3-中转站"` 区分。这个我们也是踩了坑(空中转站被误报黄)才补对。

## 四、生信学习工作流(三步链条)

三个中转站串成一条链,每个 AI 步骤:读中转站+指令 → 拼 prompt → 复制剪贴板 → 你发给 AI → 结果手动回填下一个中转站。

|中转站|放什么|配置键|
|---|---|---|
|1中转站|原始脚本|`script_transit_store`|
|2中转站|修改意见(第一步AI结果)|`script_review_result`|
|3中转站|待建笔记结果(第二步AI结果)|`script_note_source`|

**三个步骤:**

1. **脚本修改意见拼接** — 读 `评审指令` + 1中转站 → prompt → 剪贴板 → AI → 贴进2中转站
2. **分析脚本拼接** — 读 `分析指令` + 2中转站 → prompt → 剪贴板 → AI → 贴进3中转站
3. **脚本笔记创建和分发** — 读 3中转站 AI 结果 → 建笔记到 `2-生信学习/0-脚本汇总/`

前两步是纯拼接(只读+clipboard 回传,不写文件);第三步落地成笔记。

**第三步的解析规则**(动态,不预设):

- 靠 `## 笔记属性` / `## 具体笔记内容` 两个固定标题切块
- 属性行**动态解析**,有几行读几行;兼容有无序号、全角/半角冒号(防 AI 漂移)
- 「名称」→ 文件名 + 一级标题;其余属性 → frontmatter(每个 YAML 列表);值不拆分
- 正文原样写入
- **同名笔记:属性取并集(去重)、正文往下追加**,不覆盖

## 五、工作区按钮(独立机制)

按钮笔记走**精确路径**(不是配置键那套,因为它是被追加的目标,不声明配置键):

- 固定位置 `CWB_NOTE_REL = "0-辅助材料/4-工作区设置/1-工作区buttons.md"`
- **不存在就报错,绝不新建** —— 旧逻辑"不存在就创建"会在错误位置默默建文件,掩盖路径错误
- 路径相对 vault 根解析,不依赖 cwd

## 六、更新/部署逻辑(deploy.py)

**数据来源二分:**

- **GitHub 下载** —— 只有工作流内容物(`1-工作流文件/` 下那套:AI指令/辞典/中转站/说明书),来自总库 `My-Products`
- **脚本自动生成** —— 其余目录骨架,deploy 写文件时 `mkdir(parents=True)` 顺带建出来

**三个命令,更新与配置严格隔离:**

- `check` — 拉 raw version.json 比对,快判断有无新版
- `update` — 有新版才下载整库覆盖(`make_dirs=False`,**绝不初始化、不建目录树、不碰用户文件**)
- `install` — 初次安装:部署 + 建目录

**关键修正:落点 `0-工作流文件` → `1-工作流文件`**。这是目录命名问题的根源——目录名 = `WORKFLOW_DIR` 前缀(deploy 控制)+ 总库结构(GitHub 控制)。

产品名零硬编码:从 `scripts/` 上级目录自动推导,换项目自动跟随。

## 七、初始化脚本(scaffold/generator/generate)

- **scaffold.py** — 建 Tauri 应用工程外壳,把 runner/App.tsx/lib.rs/deploy 等以 base64/字符串 blob 内嵌,生成时解码落盘
- **generator.py** — tkinter GUI 壳,收集输入调 scaffold
- **generate.py** — PyInstaller 打包器,把 generator 打成 exe

**内嵌 blob 是快照,有漂移风险** —— 改了 runner/deploy/App.tsx 后,scaffold 里的副本不会自动跟着变,得手动同步(我们同步过 deploy blob)。

## 八、贯穿始终的工作原则

这些是我们协作中(有时是我犯错后)确立的铁律:

1. **绝不硬编码文件名/路径去找文件** —— 配置键靠 frontmatter 自报,程序扫描发现
2. **最小改动** —— 只改被要求的那一处,不顺手"优化"周边逻辑(我多次违反,导致把能用的 deploy 改坏)
3. **失败要响亮** —— 找不到文件就报错,绝不默默新建掩盖问题
4. **改动要能验证** —— rustc 真编译、tsc 真检查、造测试数据跑端到端,而不是靠猜
5. **数据安全优先** —— update 绝不碰用户文件,覆盖策略要明确界定
